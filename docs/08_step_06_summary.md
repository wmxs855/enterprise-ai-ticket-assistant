# 第 6 步总结：智能工单工作流

## 本步目标

把知识问答、工单分类、优先级规则和数据库操作组合成一个可解释的多步骤工作流，并加入权限、人工审批、审计日志和异常重试。

## 工作流结构

```text
用户消息
  ↓
识别任务意图
  ├─ 知识咨询 → 检索知识 → 有依据则回答 → 无依据则建议人工工单
  ├─ 创建工单 → 预测类别 → 判断优先级 → 写入数据库
  ├─ 查询工单 → 检查身份与权限 → 返回状态
  └─ 关闭工单 → 等待人工确认 → 检查权限 → 修改状态 → 写审计日志
```

## 为什么先使用确定性工作流

创建、查询和关闭工单都涉及真实数据。明确的条件分支比完全交给大语言模型更容易测试、审计和控制。后续可以让模型辅助理解自然语言，但权限与写操作规则仍应由程序强制执行。

## 安全设计

- 普通用户只能查看和关闭自己的工单。
- 关闭工单必须得到明确批准。
- 创建和关闭都会写入审计日志。
- 数据库使用参数化查询。
- 没有知识依据时只建议创建工单，不自动代替用户创建。
- 只对数据库临时错误有限重试，不对权限失败反复重试。

## 测试中发现并修复的问题

第一次运行工作流测试时，六个业务场景都完成了，但 Windows 无法删除测试数据库，提示文件仍被占用。原因是 SQLite 连接的事务上下文会提交或回滚，却不会自动关闭连接。

修复方式是增加数据库连接作用域：无论操作成功还是抛出异常，程序最终都会执行 `close` 关闭连接。这体现了文件、网络连接和数据库连接都必须显式管理生命周期。

## 面试题与参考答案

### 问题一：工作流和智能体有什么区别？

参考答案：工作流的步骤和分支主要由开发者明确规定，行为更可控；智能体通常让模型根据目标动态决定下一步。真实业务中可以组合使用，但权限、资金和删除等高风险规则不应只依赖模型判断。

### 问题二：为什么关闭工单需要人工审批？

参考答案：关闭会修改业务状态，可能影响统计和后续处理。系统先展示将要执行的操作并等待确认，可以避免意图识别错误导致误操作。

### 问题三：如何防止普通用户查询别人的工单？

参考答案：数据库查询后比较工单创建人与当前用户身份，只有创建人或管理员角色可以读取。权限必须由后端程序强制检查，不能只依赖前端隐藏按钮。

### 问题四：为什么使用参数化查询？

参考答案：参数化查询把数据库命令与用户输入分开处理，用户输入只作为数据，不会被解释为数据库命令，从而降低注入攻击风险。

### 问题五：所有错误都应该自动重试吗？

参考答案：不应该。网络波动或数据库暂时锁定可以有限重试；权限不足、输入错误和业务拒绝重试也不会成功，反而可能造成重复操作或安全风险。
