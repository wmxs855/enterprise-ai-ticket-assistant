# 项目名词表

本文件记录项目中第一次出现的技术名词。学习过程中会持续补充。

## Python

一种编程语言。它语法相对直观，并拥有大量数据处理、机器学习和人工智能开发工具，因此常用于人工智能项目。

## Git

一种版本管理工具。它可以记录文件在不同时间的变化，方便找回旧版本和多人协作。Git 不等于 GitHub；GitHub 是一个可以托管 Git 项目的网络平台。

## 项目目录

保存同一个项目全部代码、数据、文档和配置的文件夹。本项目的目录名称是 `ai-ticket-assistant`。

## 数据流

数据从输入系统开始，经过处理、存储和计算，最后形成输出结果的路径。

## 知识库

经过整理、能够被程序检索的一组资料。在本项目中，知识库主要由企业制度、产品说明和常见问题文档组成。

## 工单

对一个待处理问题的结构化记录。通常包含标题、问题描述、类别、紧急程度、提交人和处理状态等字段。

## 大语言模型

通过大量文本训练、能够理解和生成语言内容的模型。本项目不会从头训练它，而是通过网络服务调用现有模型。

## 数据库

按照一定结构保存和查询数据的软件。本项目会使用数据库保存工单，而不是把所有工单散落在普通文本文件中。

## 自动测试

用程序自动检查另一个程序是否符合预期。修改代码后重新运行自动测试，可以较快发现旧功能是否被意外破坏。

## Python 解释器

真正读取并执行 Python 程序的软件。源代码是写给人和解释器看的文本，必须交给解释器才能运行。

## 包管理工具

用于下载、安装、升级和卸载 Python 第三方工具的程序。Python 通常自带名为 `pip` 的包管理工具。

## 第三方工具

不是 Python 语言本身自带、由其他开发者发布的功能库。例如后续用于表格处理的 Pandas 就属于第三方工具。

## 隔离环境

项目专用的 Python 运行目录，其中保存该项目所需的第三方工具。不同项目使用不同隔离环境，可以避免工具版本互相冲突。本项目的隔离环境目录是 `.venv`。

## 版本管理仓库

由 Git 管理的项目目录。Git 会记录文件的新增、修改和删除，帮助开发者比较版本或恢复历史内容。

## 变量

程序中用来保存一个值的名称。例如 `urgent_count = 0` 创建了名为 `urgent_count` 的变量，并让它保存数字零。

## 字符串

由文字组成的数据，例如工单标题、问题描述和提交人姓名。Python 字符串通常写在引号中。

## 布尔值

只有“真”和“假”两种状态的数据。Python 分别使用 `True` 和 `False` 表示。在工单中，它可以表示工单是否已经关闭。

## 列表

把多个数据按顺序保存起来的容器。例如多张工单或多个紧急关键词可以保存在列表中。

## 字典

用“名称和值”的对应关系保存数据的容器。一张工单可以用字典保存编号、标题、描述、提交人和优先级。

## 条件判断

根据条件是否成立决定执行哪段程序。Python 使用 `if` 表示“如果”，使用 `else` 表示“否则”。

## 循环

让同一段程序依次处理多个数据。例如逐张显示工单，或逐个检查紧急关键词。

## 函数

一段具有名称、可以重复调用的程序。函数可以接收输入数据，也可以返回处理结果。把功能拆成函数可以减少重复代码。

## 参数与返回值

参数是调用函数时交给函数的数据；返回值是函数处理完成后交回调用位置的结果。

## 格式化字符串

一种把变量值插入文字的方法。Python 在字符串前写字母 `f`，再把变量写在花括号中。

## 自动测试断言

自动测试中用于表达预期结果的检查。如果实际结果与预期不同，断言会失败并报告具体位置。

## Pandas

一个用于读取、清洗、转换和分析表格数据的 Python 第三方工具。它的核心表格对象称为数据框。

## NumPy

一个用于批量数值计算的 Python 第三方工具。Pandas 的许多底层计算也依赖 NumPy。本项目使用它统计问题描述长度。

## 数据框

Pandas 中的二维表格对象，由行和列组成。可以把它理解成程序中的电子表格。

## 逗号分隔值文件

一种纯文本表格文件，每一行表示一条记录，字段通常使用逗号分开，文件扩展名为 `.csv`。

## 缺失值

某个字段没有提供有效内容。例如工单没有提交人或问题描述。不同字段的缺失值需要根据业务含义选择删除、填充或保留。

## 重复数据

相同记录被重复保存，或者多个记录使用同一个应该唯一的编号。重复数据会导致统计结果和模型训练产生偏差。

## 数据清洗

识别并处理缺失值、重复值、错误格式和不一致写法，使数据达到后续分析或训练可以使用的质量。

## 数据质量报告

记录原始数据存在的问题、采用的处理规则以及处理前后数量变化的文档。它让数据处理过程可以被检查和复现。

## 合成数据

为了开发或测试而人工编写、组合或生成的数据。它可以验证程序流程，但不能代替真实业务数据来证明最终效果。

## 标签

训练数据中已经知道的正确答案。本项目的标签是工单所属类别，例如“账号问题”或“支付问题”。

## 有监督学习

使用带有正确答案的数据训练模型，让模型学习输入与答案之间的关系，再对新输入作出预测。

## 训练数据与测试数据

训练数据用于让模型学习；测试数据只用于训练结束后的效果检查。测试数据不能提前参与训练，否则评测结果会失真。

## 特征

模型用于作出判断的数字化信息。文本不能直接交给大多数传统机器学习模型，因此需要先转换成数字特征。

## 词频—逆文档频率

一种文本数字化方法。一个词或字符在当前文本中经常出现会提高权重，但如果它在所有文本中都很常见，权重会降低。

## 逻辑回归

一种名称中带有“回归”、但常用于分类的机器学习方法。它学习不同文本特征对各类别的影响，并选择得分最高的类别。

## 基准模型

用于比较的简单方法。本项目的基准永远预测训练数据中最常见的类别。正式模型只有明显超过基准才说明学习产生了价值。

## 准确率

全部预测中，预测正确的数量所占比例。

## 精确率

模型预测为某个类别的样本中，真正属于该类别的比例。

## 召回率

真正属于某个类别的样本中，被模型成功找出的比例。

## 调和平均指标

综合精确率和召回率的指标。只有两者都较高时，这个指标才会较高。

## 混淆矩阵

按真实类别和预测类别排列的计数表，用于观察模型经常把哪一类错误判断成哪一类。

## 数据泄漏

训练阶段意外使用了本应只在评测阶段出现的信息，导致测试结果虚高。例如先对全部数据学习文本特征，再划分测试数据。

## 随机种子

控制随机过程的固定数字。使用相同数据、代码和随机种子，可以得到相同的数据划分，便于复现实验。

## 模型保存

把训练完成的模型参数和处理步骤写入文件，后续预测时可以直接加载，不需要每收到一张工单就重新训练。

## 预测概率

模型对不同类别给出的相对分数经过转换后的结果。最高概率可以帮助设置人工复核条件，但它不天然等于真实世界中预测正确的概率，需要额外校准和验证。

## 错误分析

逐条查看模型预测错误的样本，分析错误是否来自数据不足、类别定义重叠、文本歧义或模型能力限制，再决定下一轮改进方向。

## Markdown 文档

使用简单符号表示标题、列表和代码等结构的纯文本文件，扩展名为 `.md`。它便于阅读、版本管理和程序解析。

## 文本切分

把长文档拆成较短、含义相对完整的片段。片段过长会混入无关内容，片段过短又可能丢失必要上下文。

## 检索

根据用户问题，从一组文档片段中寻找最相关内容的过程。

## 文本向量

用一组数字表示文字内容。文字必须先转换成数字，程序才能计算两个文本的相似程度。

## 余弦相似度

比较两个向量方向是否接近的方法。结果越大，通常表示问题与文档片段越相似，但相似度不等于事实正确性。

## 相关度阈值

系统接受检索结果所要求的最低分数。最高结果低于阈值时，系统选择拒绝回答并转交人工，而不是勉强返回无关内容。

## 来源引用

回答同时标明依据来自哪个文件和哪个章节，使用户能够检查答案，也方便后续追踪错误。

## 幻觉

大语言模型生成听起来合理、但没有事实依据或与资料冲突的内容。可靠的检索和来源引用可以降低风险，但不能保证完全消除。

## 提示词

发送给大语言模型的文字输入，包括任务说明、用户问题、参考资料和输出要求。提示词会影响模型如何组织答案，但不能替代测试。

## 高优先级指令

由应用开发者提供、用于规定模型角色和行为边界的指令。用户问题和检索资料不能覆盖这些安全要求。

## 上下文

模型生成当前答案时能够看到的全部文字。本项目的上下文包含用户问题和检索到的参考资料。

## 环境变量

由操作系统或运行环境保存的配置值。密钥放在环境变量中，可以避免直接写进源代码和版本管理仓库。

## 模型服务密钥

调用在线模型服务时用于确认账户和权限的秘密字符串。密钥不能写入代码、提交到 Git 或显示在日志中。

## 依赖注入

程序从外部接收所需组件，而不是在内部固定创建。本项目把答案生成器传给知识助手，因此在线模型、离线模式和测试模拟器可以互换。

## 失败回退

主要功能不可用时采用的安全替代方案。本项目在模型服务异常时直接返回检索原文和来源。

## 提示词注入

攻击者在用户输入或文档中写入恶意指令，试图让模型忽略原有规则、泄露信息或执行越权操作。本项目把检索资料标记为不可信证据，并规定其中的指令不得执行。

## 工作流

按照明确步骤、条件和状态执行任务的程序。本项目的工作流负责判断意图、选择工具、检查权限和组织结果。

## 意图识别

判断用户希望完成哪类任务，例如知识咨询、创建工单、查询进度或关闭工单。

## 工具调用

工作流调用一个职责明确的程序函数完成操作，例如检索知识、预测类别、写入数据库或查询工单。

## 执行轨迹

记录工作流识别了什么意图、调用了哪些工具以及在哪里暂停。它有助于调试和审计。

## SQLite

一种把完整数据库保存在单个本地文件中的关系型数据库。它不需要单独启动数据库服务器，适合学习、测试和单机演示。

## 参数化查询

把数据库命令和用户数据分开传递。这样用户输入不会被当作数据库命令执行，可以降低数据库注入攻击风险。

## 事务

一组要么全部成功、要么全部失败的数据库操作。创建工单和写入对应审计日志应保持一致。

## 权限控制

根据用户身份和角色限制可查看或修改的数据。普通用户只能处理自己的工单，管理员拥有更大的业务权限。

## 审计日志

记录谁在什么时间执行了什么重要操作。它用于追踪问题、安全检查和责任确认。

## 人工审批

敏感操作执行前由人明确确认。模型或工作流不能因为推测用户意图就自动执行删除、关闭或付款等操作。

## 有限重试

遇到可能暂时恢复的错误时再次尝试，但设置明确次数，避免程序无限循环。本项目只对数据库临时错误进行有限重试。

## 后端服务

在用户界面背后接收请求、执行规则、访问模型或数据库并返回结果的程序。本项目后端服务把已经完成的知识问答和工单工作流开放给浏览器或其他程序。

## 应用程序编程接口

英文全称是 Application Programming Interface。它规定两个程序如何交换数据，例如请求应发送哪些字段、使用哪个网络地址、会返回哪些结果。招聘描述中常写成 API，本项目文档优先使用中文全称。

## 端点

后端服务提供的一条具体访问路径。不同端点分别负责健康检查、知识咨询、创建工单、查询工单和关闭工单。

## 超文本传输协议

英文全称是 Hypertext Transfer Protocol，是浏览器和后端服务传递请求与响应时常用的网络规则。招聘描述和工具输出中常写成 HTTP。

## 请求与响应

请求是调用方发给后端的数据和操作意图；响应是后端处理后返回的状态、业务数据或错误信息。

## JavaScript 对象表示法

英文全称是 JavaScript Object Notation，是网络接口常用的文本数据格式，使用名称和值组织信息。招聘描述中常写成 JSON。虽然名称包含 JavaScript，但 Python 等语言也能读写这种格式。

## 数据结构校验

在业务逻辑执行前检查输入字段是否存在、类型是否正确、长度是否合理；也可检查输出是否符合公开约定。本步的响应校验发现了来源字段不一致问题。

## 网络状态码

响应中表示处理结果类别的数字。例如 200 表示请求成功，201 表示数据创建成功，403 表示禁止访问，404 表示没有找到资源，409 表示当前操作存在需要处理的冲突，422 表示输入不符合结构要求。

## FastAPI

一个用于编写 Python 后端服务的第三方工具。它能根据 Python 类型提示校验数据，并自动生成可交互的接口文档。

## Uvicorn

一个负责运行 Python 网络应用的服务程序。FastAPI 定义“服务提供什么功能”，Uvicorn 负责监听本机网络端口并把请求交给应用处理。

## 健康检查

用于确认服务进程可以正常响应的轻量接口。它通常只返回状态和版本，不执行复杂业务。

## 超文本标记语言

英文全称是 HyperText Markup Language，用标签描述网页中的标题、表单、按钮等内容结构。招聘材料中常写成 HTML。

## 层叠样式表

英文全称是 Cascading Style Sheets，用于控制网页的颜色、间距、字体、布局和不同屏幕下的显示方式。招聘材料中常写成 CSS。

## JavaScript

一种主要在浏览器中运行的编程语言。本项目用它读取表单、向后端发送请求并把返回结果更新到页面。

## 文档对象模型

英文全称是 Document Object Model，是浏览器把网页内容转换成的对象树。JavaScript 可以安全地创建或修改树中的文字和元素。招聘材料中常写成 DOM。

## 静态资源

不需要后端实时计算、可以直接发送给浏览器的文件，例如网页结构文件、样式文件和交互脚本。

## 前后端分离

用户界面负责收集输入和展示结果，后端负责业务规则、权限、模型与数据库。双方通过应用程序编程接口交换数据，因此可以独立修改和测试。

## 响应式布局

让同一个网页根据屏幕宽度自动调整列数、间距和按钮排列，使电脑与手机都能正常使用。

## 脚本注入

攻击者设法把恶意脚本混入页面并让浏览器执行。本项目显示接口结果时使用纯文本节点，不把用户输入直接当作网页代码解释，从而降低这类风险。

## 模块

一个职责相对集中的 Python 文件。例如 `knowledge_base.py` 是知识检索模块，`ticket_database.py` 是数据库模块。使用模块可以避免把所有代码堆在一个文件中。

## 导入

在一个 Python 文件中使用另一个模块提供的函数或类。Python 使用 `import` 语句完成导入，本项目的接口层正是通过导入工作流来复用业务规则。

## 类与对象

类是一组数据和行为的设计说明，对象是根据这份说明创建出的具体实例。例如 `TicketRepository` 是类，连接某个具体数据库文件的 `repository` 是对象。

## 装饰器

写在函数上方、以 `@` 开头的 Python 语法，用于在不改写函数主体的情况下附加行为。FastAPI 使用装饰器把函数登记为某个网络端点。

## 序列化

把程序中的对象转换成可以保存或通过网络传输的数据格式。后端把 Python 字典序列化成 JavaScript 对象表示法后发送给浏览器。

## 仓库模式

把数据库读写集中在专门的类中，让业务工作流不需要直接编写数据库命令。本项目的 `TicketRepository` 负责创建、查询、关闭和审计。

## 机器学习流水线

把多个连续处理步骤组合成一个整体。本项目把文本数字化和逻辑回归放在同一条流水线中，训练、预测和保存时始终使用相同顺序。
