# 项目概览

## 要解决的问题

企业内部经常存在大量制度文档、产品手册和历史问题记录。员工遇到问题时，可能不知道应该查哪份文档，也不知道应该联系哪个部门。

本项目将实现下面的处理流程：

1. 用户输入问题。
2. 系统从企业文档中寻找相关内容。
3. 找到可靠依据时，系统生成答案并显示来源。
4. 找不到可靠依据时，系统询问创建工单需要的信息。
5. 系统判断工单类别和紧急程度。
6. 系统将工单保存到数据库。
7. 用户可以查询工单处理状态。

## 为什么选择这个项目

它同时覆盖数据处理、机器学习、知识库检索、大语言模型调用、工具调用、后端接口、数据库、测试和安全设计，集中展示一套人工智能应用从实验到可运行演示的工程流程。

## 实现边界

本项目追求可以运行、可以解释、可以测试的本地演示，不把它包装成已经能够支持大型企业的生产系统。

本阶段不会从头训练大语言模型，也不会开发复杂网页。我们会优先保证核心流程完整，并确保每项简历描述都有代码或实验结果作为证据。

## 最终数据流

“数据流”表示数据从进入系统到产生结果所经过的路径。

```text
用户问题
  ↓
意图判断：咨询问题，还是办理工单
  ↓
咨询问题 → 检索企业文档 → 生成带来源的回答
  ↓ 无可靠答案
创建工单 → 判断类别和紧急程度 → 保存到数据库
```

## 完成标准

- 能够读取并清洗工单数据。
- 能够训练和评估一个工单分类模型。
- 能够根据企业文档回答问题并显示来源。
- 没有可靠资料时不会编造答案。
- 能够创建并查询工单。
- 模型或数据库失败时有明确错误提示。
- 有测试问题、实验结果、项目说明和技术文档。
