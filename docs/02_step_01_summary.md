# 第 1 步总结：环境与项目骨架

## 本步目标

确认电脑能够运行 Python，并建立一个结构清晰、不会与其他项目依赖冲突的项目目录。

## 已完成内容

1. 检查工作区，确认开始时没有旧项目文件。
2. 确认 Git 已安装。
3. 从 Python 官方网站获取并验证安装程序。
4. 将 Python 3.12.10 安装到 D 盘。
5. 在项目内部创建隔离环境 `.venv`。
6. 创建数据、文档、源代码和测试目录。
7. 创建环境检查程序。

## 为什么这样做

- 固定 Python 版本可以减少“在一台电脑能运行、换一台电脑却失败”的情况。
- 使用隔离环境可以防止不同项目所需的工具版本发生冲突。
- 提前规划目录可以避免代码、数据和文档混在一起。
- 环境检查程序可以把人工检查变成可重复执行的检查。

## 本步知识点

- Python 源代码需要 Python 解释器执行。
- 第三方工具由包管理工具安装。
- 每个项目应使用独立的隔离环境。
- Git 用于记录项目文件的版本变化。
- 项目骨架负责规定不同类型文件的存放位置。

## 自测问题

1. Python 源代码和 Python 解释器有什么区别？
2. 为什么不同项目最好使用不同的隔离环境？
3. `src`、`data`、`docs` 和 `tests` 分别保存什么？
4. Git 和 GitHub 是同一个东西吗？

## 面试题与参考答案

### 问题一：为什么项目需要隔离环境？

参考答案：不同项目可能依赖同一个工具的不同版本。隔离环境把每个项目的第三方工具分开保存，避免升级一个项目的工具后破坏另一个项目，同时也方便复现运行环境。

### 问题二：你如何保证项目在其他电脑上可以运行？

参考答案：我会固定 Python 和第三方工具版本，提供依赖清单、环境检查程序和启动说明，并在干净环境中重新安装和运行测试。后续还可以使用容器进一步统一运行环境。

### 问题三：为什么代码、数据、文档和测试要分目录？

参考答案：不同类型文件的用途和变化频率不同。分目录可以降低查找和维护成本，也便于设置版本管理规则，例如忽略运行时数据库和私密配置。

### 问题四：Git 和 GitHub 有什么区别？

参考答案：Git 是安装在电脑上的版本管理工具；GitHub 是托管 Git 仓库并支持协作的网络平台。项目可以只使用 Git，不上传到 GitHub。
