# 第 7 步第二部分总结：可视化演示页面

## 本步目标

给后端服务增加一个真正调用业务接口的网页，让面试官不需要阅读代码就能看到知识检索、自动分类、权限查询和人工审批的完整流程。

## 页面使用的三个基础技术

1. 超文本标记语言负责页面结构，例如标题、输入框、按钮和结果区域。
2. 层叠样式表负责颜色、字体、卡片、两栏布局和手机屏幕适配。
3. JavaScript 负责监听按钮、向后端发送请求、处理错误并更新页面。

这里没有使用大型前端框架。原因不是框架没有价值，而是本项目只有一个演示页面，原生技术已经足够；在 3–5 天准备期内，更重要的是理解前端如何调用后端，而不是增加构建工具和抽象层。

## 前后端数据流

```text
填写问题或工单描述
        ↓
JavaScript 把表单转成网络请求
        ↓
FastAPI 校验输入并调用工作流
        ↓
工作流调用知识检索、分类模型或数据库
        ↓
后端返回 JavaScript 对象表示法数据
        ↓
JavaScript 使用纯文本节点更新结果区域
```

## 安全与易用性设计

- 接口结果使用 `textContent` 写入页面，不把用户内容解释成网页代码，降低脚本注入风险。
- 所有表单都有明确标签，键盘和辅助阅读工具能够识别。
- 服务状态会在页面顶部自动检查。
- 创建成功后自动把工单编号填入查询区域，减少演示时手工复制。
- 关闭按钮不会绕过后端审批；未勾选确认时，后端仍返回 409。
- 页面明确展示合成数据、离线评测和模拟身份的限制。
- 屏幕变窄后，两栏会自动变成单栏。

## 真实浏览器验收结果

1. 页面加载并显示服务版本 `0.7.0`。
2. 差旅问题返回“五百元”及 `reimbursement_policy.md` 来源。
3. “员工无法登录内部系统”创建为账号问题、紧急工单。
4. 创建后编号自动填入，查询返回待处理。
5. 未确认关闭时显示阻断信息。
6. 确认后工单变为已关闭，并提示已经写入审计日志。
7. 完整自动测试 37 项全部通过。

## 三分钟演示顺序

### 第一分钟：知识问答

点击“差旅标准”，说明系统不是让模型凭记忆回答，而是先检索企业文档。指出回答下方的文件名、章节和相关度；再强调低于阈值时系统会拒绝回答并建议创建工单。

### 第二分钟：创建与分类

使用默认描述“员工无法登录内部系统”创建工单。指出系统使用已保存的文本分类模型判断为账号问题，并由明确规则判断为紧急，然后写入 SQLite 数据库和审计日志。

### 第三分钟：权限与审批

查询刚创建的工单。先不勾选确认直接关闭，展示后端拒绝；再勾选并关闭。说明高风险写操作由程序规则约束，不能仅依靠大语言模型自行决定。

## 本步相关文件

- `web/index.html`：网页内容结构。
- `web/styles.css`：视觉设计与响应式布局。
- `web/app.js`：调用后端和更新页面。
- `src/api.py`：返回主页和静态资源。
- `tests/test_api.py`：增加主页与静态资源测试。
- `start_demo.bat`：双击启动本地服务。

## 面试题与参考答案

### 问题一：网页如何与 Python 后端通信？

参考答案：JavaScript 使用浏览器的 `fetch` 函数发送网络请求。后端校验输入并返回 JavaScript 对象表示法数据，页面再把需要的字段显示出来。

### 问题二：为什么不使用 Vue 或 React？

参考答案：当前只有一个状态较少的演示页面，原生 JavaScript 已能清晰完成需求。选择技术应匹配复杂度。若后续扩展路由、多人协作和复杂状态管理，再引入前端框架更合理。

### 问题三：为什么前端已经要求确认，后端还要再次检查？

参考答案：调用者可以绕过网页直接请求后端，因此前端限制只改善交互，不能构成安全边界。审批、权限和数据校验必须由后端强制执行。

### 问题四：页面如何降低脚本注入风险？

参考答案：接口返回的回答和工单内容通过 `textContent` 作为普通文字写入，不使用 `innerHTML` 把它们当作网页代码执行。生产环境还需要安全响应头、依赖审计和系统化安全测试。

### 问题五：什么是响应式布局？

参考答案：页面根据屏幕宽度改变布局。本项目在宽屏使用两栏，在窄屏改成单栏，并调整导航和按钮排列，让电脑与手机都可使用。
