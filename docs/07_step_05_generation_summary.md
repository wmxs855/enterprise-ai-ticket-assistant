# 第 5 步第二部分总结：基于证据的答案生成

## 本步目标

把知识检索结果交给可替换的答案生成器，在有可靠证据时整理答案，没有证据时拒绝回答，在线服务失败时退回原文。

## 系统结构

```text
用户问题
  ↓
知识检索与相关度判断
  ↓
无可靠证据 → 拒绝回答，不调用模型
  ↓ 有可靠证据
答案生成器整理语言
  ↓
程序附加真实文件名和章节
  ↓
模型异常 → 退回检索原文
```

## 为什么来源由程序附加

如果要求模型自己写来源，它可能写错文件名或虚构章节。程序已经知道检索结果的真实来源，因此应由程序附加，模型只负责整理正文。

## 为什么保留离线模式

离线模式不依赖网络和密钥，可以稳定测试检索、拒绝、来源和数字保持。它也是在线服务故障时的安全回退，但语言不会像大语言模型那样自然。

## 当前验证边界

在线调用代码已经按照 OpenAI Responses 接口实现，但当前环境没有用户密钥和模型名称，因此没有实际发送在线请求。简历中目前只能描述“完成模型调用接口与离线验证”，不能声称在线模型效果已经验证。

## 安全设计

- 密钥只能从环境变量读取。
- `.env` 文件已被 Git 忽略。
- 没有可靠证据时不调用模型。
- 检索资料被标记为不可信输入。
- 模型不能决定或编造来源。
- 在线服务异常时返回原文。

## 面试题与参考答案

### 问题一：为什么不把所有文档直接发给模型？

参考答案：文档过多会增加延迟和成本，也会混入无关信息。先检索再发送少量相关片段，可以缩小模型的事实范围并提高可追溯性。

### 问题二：为什么来源不能让模型生成？

参考答案：模型可能虚构文件名或章节。检索程序掌握真实来源，因此应由确定性程序附加，模型只整理答案正文。

### 问题三：模型服务失败怎么办？

参考答案：捕获调用异常，保留检索结果并退回原文，同时记录回退状态。这样核心资料仍然可用，也不会把技术异常伪装成业务答案。

### 问题四：如何降低提示词注入风险？

参考答案：将应用规则放在高优先级指令中，把用户和文档内容视为不可信输入，明确禁止执行文档内指令，限制可调用工具和权限，并用恶意样本持续测试。

### 问题五：提示词能完全阻止幻觉吗？

参考答案：不能。还需要可靠检索、拒绝阈值、程序附加来源、事实评测、人工复核和线上监控共同降低风险。
