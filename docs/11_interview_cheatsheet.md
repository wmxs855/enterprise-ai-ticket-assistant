# 企业知识库与智能工单助手：面试速记

## 三十秒项目介绍

我独立完成了一个企业知识库与智能工单助手。用户可以查询企业制度，系统先检索本地文档，只有相关度达到阈值才回答并附来源；无法回答时建议创建工单。工单会由文本分类模型自动分类，并通过确定性工作流完成权限检查、人工审批和审计记录。我把功能封装成 FastAPI 后端并制作了网页演示，当前 37 项自动测试全部通过。项目数据是合成数据，所以我把结果定位为流程验证，不宣称生产效果。

## 两分钟项目介绍

这个项目解决两个问题：员工找制度慢，以及知识库答不上来后缺少人工处理闭环。

数据层面，我先清洗工单数据，处理缺失、重复和类别不统一；再用一百二十条平衡合成数据训练文本分类模型。模型把词频—逆文档频率特征和逻辑回归封装在同一条流水线中，固定测试集准确率为 96.7%，明显高于 23.3% 的简单基准，但这个结果只说明模型能学习当前合成数据规律。

知识问答层面，我把四份 Markdown 文档按章节切成十六个片段，使用字符级词频—逆文档频率向量和余弦相似度检索。十六个已知问题首位命中，四个知识库外问题全部拒绝。回答由程序附加来源，在线模型失败时回退到原始证据。

工程层面，我用工作流连接知识检索、分类、优先级、SQLite 数据库、权限、人工审批和审计日志，再用 FastAPI 提供网络接口。关闭工单必须明确确认，普通用户不能查询别人的工单。最后制作真实调用后端的网页，并完成 37 项自动测试和 6 项接口场景评测。


## 简历项目表述

项目名称：企业知识库与智能工单助手

- 使用 Python、Pandas 完成工单数据清洗与质量报告，构建一百二十条四分类平衡合成数据集，并使用词频—逆文档频率与逻辑回归实现工单分类；固定测试集准确率 96.7%，相较 23.3% 简单基准显著提升。
- 实现带来源引用和拒答阈值的企业文档检索，在十六条已知问题离线评测中首位命中 16/16，并对四条知识库外问题全部拒答；支持大语言模型调用适配与服务失败回退。
- 设计知识问答、创建、查询和关闭工单工作流，加入普通用户数据隔离、人工确认、参数化数据库查询、审计日志与有限重试。
- 使用 FastAPI 封装后端服务并实现响应式演示页面，覆盖正常、边界、异常和安全场景；完成 37 项自动测试与 6 项接口评测。

面试时必须主动补充：分类和检索数字来自合成数据及小规模离线测试，不代表真实生产效果。

## 最可能被追问的问题

### 1. 这算检索增强生成吗？

回答：核心链路符合“先检索证据，再基于证据生成答案”的思想。当前默认使用离线证据生成器，已经预留在线大语言模型适配，但还没有用我自己的有效密钥完成在线验证。因此我会称它为可切换生成器的检索问答原型，而不会声称在线生成已经验证。

### 2. 为什么没用向量数据库？

回答：当前只有十六个片段，内存矩阵更简单、可测试，也避免不必要的基础设施。数据扩大后，我会把向量持久化到向量数据库，增加增量索引、元数据过滤和版本管理。项目已经把检索逻辑封装，便于替换。

### 3. 为什么不用 LangChain 或 LangGraph？

回答：我先手写小型工作流，是为了理解意图路由、工具调用、状态、审批和异常处理的底层机制，而不是只会调用框架。复杂度增加到多轮状态、分支恢复和长时间任务时，我会评估使用 LangGraph；选择框架要解决实际复杂度，而不是为了堆技术名词。

### 4. 为什么分类准确率很高？

回答：数据是规则组合出的平衡合成数据，类别词比较明显，因此 96.7% 不代表真实业务泛化能力。上线前需要匿名真实数据、时间切分、人工复核、类别不平衡指标、置信度校准和持续错误分析。

### 5. 检索为什么使用字符特征？

回答：中文不天然以空格分词，字符级二元到四元组合不依赖额外分词器，也能捕捉“无法登录”“重复扣款”等短语。局限是语义改写能力较弱，后续可加入语义嵌入、关键词检索融合和重排序模型。

### 6. 如何减少大语言模型幻觉？

回答：先设置检索阈值，没有可靠证据时拒答；提示词规定只能使用提供的资料；来源由程序而不是模型附加；保留离线回退；再用包含数字、边界和无答案问题的评测集持续检查。仍不能保证完全消除，所以高风险操作不交给模型直接执行。

### 7. 权限设计有什么问题？

回答：业务层已经强制普通用户只能访问自己的工单，但当前身份由请求参数模拟，调用者能够伪造管理员。生产环境需要接入身份认证，使用服务端验证的会话或签名凭证，并补充角色与资源级授权。

### 8. 为什么关闭用 POST 而不是 DELETE？

回答：关闭是业务状态变化，记录仍需保留用于审计，并不真正删除资源，所以使用动作端点更符合当前语义。若设计更严格的资源接口，也可以通过更新工单状态表达。

### 9. 为什么数据库用 SQLite？

回答：它无需单独启动服务，适合本地学习、测试和单机演示。生产并发场景会换成服务型关系数据库，并考虑连接池、迁移、索引、备份和事务隔离。

### 10. 下一步怎么做？

回答：第一，接入匿名真实数据并重做分类与检索评测；第二，加入语义嵌入、关键词与语义混合召回、重排序；第三，完成真实身份认证与资源授权；第四，增加日志、监控、并发压力测试和容器化部署；第五，再验证在线模型质量、成本和失败策略。

## 不要说的内容

- 不要说“模型准确率已经达到生产要求”。
- 不要说“使用了向量数据库”，当前没有。
- 不要说“已经完成真实身份认证”，当前只是模拟身份。
- 不要说“已经验证在线大语言模型”，尚未使用用户密钥验证。
- 不要把明确分支的工作流夸大成完全自主智能体。
- 不要背数字却解释不出数据如何产生。

3. 能画出数据清洗、分类、检索和工作流四条链路。
4. 能解释 96.7%、16/16、6/6 和 37/37 分别测了什么、没测什么。
5. 熟记三个诚实边界：合成数据、模拟身份、在线模型未验证。
6. 准备一个“测试发现接口字段不一致”和一个“数据库连接未关闭”的排错故事。
